# 方案二：自建连接 + 系统路由分流（2026-11-05 用户选定，分批计划草案，待确认）

取代原分批计划第 2 批起的 mihomo 路线（见架构审查
[architecture-review-2026-11-05.md](architecture-review-2026-11-05.md)）。第 1 批"自建连接"保留（已实测可用）。

## 目标与边界

- 只有一条隧道（openconnect），一个路由所有者（后台服务）；不再叠第二个 TUN、不再有用户态分流核心。
- 按**域名**分流：名单里的域名（如 example.com）走本地网络，其余全部走 VPN。
  不做按应用、按单条连接分流（没有开发者账号时，这两样必须靠用户态核心，正是第 2 批出事的那层）。
- 断线保护（用户定）：只拦"本该走 VPN"的流量；名单里直连的域名在 VPN 掉线时照常可用。
- "经 Cisco"连接方式保留，在方案二实测通过前仍是你的日常方式。

## 怎么做（大白话）

1. **改动台账**：后台服务每改一处系统网络（路由、系统 DNS 条目、防火墙规则、我们起的进程），先记账再动手；
   断开、退出、崩溃后重启、开机、一键恢复都只调用同一个"按台账全部撤销"。vpnc-script 只负责给隧道网卡配地址并通知，
   路由和 DNS 改由后台服务按台账做——不再有四处各写一套撤销。
2. **本机 DNS 转发**：系统 DNS 指向后台服务在本机开的转发器，后面跟着隧道 DNS 作备用（转发器挂了，系统自动改用隧道 DNS，
   只是暂时不分流，不会断网）。查询名单里的域名时，转发器向本地网络的 DNS 查询，先给得到的地址加"经本地网卡"的主机路由、
   放进防火墙的直连地址表，再把答案交给程序；其余域名经隧道向公司 DNS 查询。第一台 DNS 不通时换下一台、再试 TCP（PoC 实测需要）。
3. **防火墙**：本地网卡只放行网关、家里局域网、DHCP、本地网络的 DNS 和直连地址表；连上与掉线用同一套规则，
   所以掉线时直连的域名照常可用，走 VPN 的流量被拦住。防火墙写入归"网络闸门"（另一个 Thread 负责），我通过 Coordinator 与它对接。
4. **设置**：一页"不走 VPN 的网站"，预置几个常用网站组可勾选，也能自己加；改动即时生效。

| 批次 | 内容 | 验收（每次实测都自带自动回退：连通性探测失败即按台账撤销、恢复直连） |
| --- | --- | --- |
| A 地基 | 改动台账 + 统一撤销；vpnc-script 变薄；删掉 mihomo 分流核心、透明代理扩展、数据泵等不用的组件 | CI：台账与撤销的单元测试、路由计划桩测试；本机：自建连接照常可用，断开、退出、强杀后路由与系统 DNS 无任何残留 |
| B 域名分流 | DNS 转发器、主机路由、直连地址表、设置页、断线保护新语义 | CI：转发器与名单匹配测试；本机：名单域名出口为本地宽带、其余为公司出口；掉线时直连可用、VPN 流量零泄漏；断开后无残留 |
| C 细节 | IPv6（名单域名只给 IPv4 答案，避免绕行）、睡眠唤醒与换网络、长时间运行 | 本机分项实测 |

已知限制（会写进文档）：程序自己用加密 DNS（DoH）时绕过本机转发器，名单对它不生效，它的流量仍走 VPN；
同一个 CDN 地址若同时承载名单内外的服务，会一起直连。

## 安全做法（用户的硬要求）

- 每次会动网络的实测前：恢复工具就位（面板"恢复网络"、桌面"AlwaysConnect 恢复网络"）；
  测试脚本自己定时探测，不通就撤销改动恢复直连，不需要你在断网时找我。
- 在 B 批实测通过前，"经 Cisco"仍是默认连接方式。
