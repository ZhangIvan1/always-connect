- [ ] 旧版或未知后台服务下延迟 getStatus 回复，提交 blocking/connected 后手动断开、等待 Cisco 本地停止且网络未封，再送达旧回复；不得再次封网。强制恢复、按需断开、切换模式同样取消旧保护。

### I37. 停止连接尝试：按需断开与无物理网络暂停（外部贡献；DESIGN §46.12、§四十八，均需实测）

- [ ] Cisco 登录准备或网关超时中命中按需断开/手动断开：不再提交迟到登录，守护进程停止尝试，面板不残留登录中；断开完成后恢复直连，换网仅按规则恢复（§46.12）。
- [ ] Cisco 正在网关超时/手机确认中，物理网络连续两秒无路由：停止 CLI 并由 vpn disconnect 取消守护进程尝试，面板显示「等待网络恢复」，不再定期登录。
- [ ] 已封网时离线仍封网，连接中进入离线等待要收紧为 blocking；自建子进程退出及旧保护回复不恢复直连；断线保护关闭时不擅自开启。
- [ ] 网络恢复立即连接；无网时手动断开、退出或按需暂停后，恢复网络不得覆盖停止意图。
- [ ] 小于两秒抖动不暂停，连续变化的旧截止无效；IPv4、IPv6-only、Wi-Fi/有线/热点切换、合盖唤醒均正确识别 en*，不把 utun 当作物理网络。
- [ ] 自建方式无网停止 openconnect 与 respawn，网络在子进程退出前恢复也只连接一次；旧重试计时不重复派生。
- [ ] 对照 main/本分支的在线空闲、离线等待，记录 footprint、CPU、idlew（§32、§48.3），确认离线唤醒下降、在线无退化。
